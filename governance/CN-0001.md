## What changed

Validator **v1.2.0** (released 2026-05-21) widened annotation-rule enforcement:

- Rules **A002 / A003** were extended from segmentation sidecars to all five spec-defined annotation suffixes (`_seg`, `_bbox`, `_cls`, `_lm`, `_roi`).
- Rules **A004 / A005** were extended to require `VIDSVersion` and a conformant `Provenance` block on **every** annotation sidecar, where earlier validators inspected only `*_seg.json`.

## Why

SPEC §10.1 has marked `VIDSVersion` and `Provenance` **REQUIRED** on every annotation sidecar since VIDS 1.0. Validator 1.1.x enforced them only on `*_seg.json` sidecars. Validator 1.2.0 expanded enforcement to match existing Core Specification requirements across all annotation types. It was a conformance correction for previously under-enforced REQUIRED fields, not a new requirement.

## Impact

The correction produced new FAIL outcomes that earlier validators did not report. A dataset carrying a `_bbox`, `_cls`, `_lm`, or `_roi` sidecar that lacks `VIDSVersion` or a conformant `Provenance` block **passed under validator 1.1.x and fails under 1.2.x** (a PASS→FAIL transition).

No published VIDS dataset is affected:

- **LIDC-Hybrid-100** - segmentation-only; validates 21/21 under 1.2.1.
- **IDRiD fundus** reference implementation - validates 15/21 PASS under 1.2.1.

No published VIDS dataset requires migration. Because no published adopter dataset is affected, no additional adopter notification beyond the published release documentation is required.

## Compatibility

- The PASS→FAIL transition affects only datasets that were passing solely because an earlier validator under-enforced a REQUIRED field.
- The `ValidatorVersion` emission note applies to **1.2.0 only**; validator **1.2.1** emits `1.2.1`.
